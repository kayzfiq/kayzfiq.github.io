Disk Monitoring Essentials for Linux SysAdmins

Disk issues are silent killers of performance. A saturated disk can make your CPU look slow and your memory appear insufficient. Here’s how to monitor disk health effectively.

Two critical aspects: Space and performance

Most Admins only check disk space, but disk I/O performance is equally critical. You need to monitor both!

Disk space monitoring basics:

Filesystem usage

df -h

Find what’s consuming space

du -sh /var/log/*

du -sh /home/*

Use ncdu command for interactive exploration

Warning thresholds

  • > 80% full = start planning cleanup
  • >90% full = urgent attention needed
  • >95% full = performance degradation, possible failures

Many filesystems slow down significantly when nearly full.

The hidden problem: Inodes

You can run out of inodes (file slots) even with plenty of space remaining!

Check inode usage

df -i

If inode usage hits 100%, you can not create new files even with free space.

Quick Space Recovery

Find large files

find / -type f -size +1G -exec ls -lh {} \;

Find old log files

find /var/log -type f -mtime +30 -size +100M

Check deleted files still help open (space not freed)

lsof | grep deleted

Restart services holding deleted files to actually free the space.

Disk I/O Performance: critical part

understanding iostat

iostat -x -h 1

Key metrics to watch

%util - Disk utilization percentage

  • <60% = Healthy
  • 60-80% = Getting busy
  • >90% = Saturated, performance degrading
  • 100% = Disk bottleneck

await - Average wait time for I/O requests (milliseconds)

  • NVMe: <10ms = Good
  • SSD: <20ms = Acceptable
  • HDD: <30ms = Normal
  • >100ms = Problem regardless of disk type

r/s&w/s - Reads and writes per second. Helps identify read-heavy vs write-heavy workloads.

rkB/s&wkB/s - Throughput in KB/s.

Finding I/O Hogs

iotop #Which processes are doing I/O

iotop -o #Sort by I/O usage

iotop -b -n 3 #Non-interative mode

Disk Errors and Health

Check for hardware issues

dmesg | grep -i "error\|fail" #kernel ring buffer for disk errors

smartctl -a /dev/sda #smart data for disk health

SMART attributes to watch for:

  • Reallocated sectors - should be 0
  • Current pending sectors - Growing numbers = failing disk
  • Temperature - Keep below 50C for HDDs, 70C for SSDs

The I/O Wait Mystery Solved

Remember from CPU monitoring? High %wa(I/O wait) in top command points to disk issues.

Correlation checks:

# Terminal 1: watch CPU 
top

# Terminal 2: watch disk 
iostat -x 1

If CPU shows high wa AND iostat shows high %util or await, you’ve found your bottleneck.

Common Disk Scenarios

Scenario 1: Database slowdown:

iostat -x 1
# Shows: %util at 100%, high await times
iotop
# Shows: postgres/mysql doing heavy writes

Solution: Optimize queries, add indexes, consider faster storage, or implement read replica.

Scenario 2: Log Explosion

df -h
# Shows: /var at 95%
du -sh /var/log/*
# Shows: application.log at 50GB

Solution: Implement log rotation, compress old logs or move to centralized logging.
